# Research: 三路线学习与学情闭环 — 技术决策

> Phase 0 产物。解决 plan.md Technical Context 中的未知项。格式：Decision / Rationale / Alternatives。

## D1 掌握度算法选型

- **Decision**: 采用「加权评分 + 五级阈值映射」。每个知识点的掌握分 = 加权组合：章节测试正确率（权重 0.60）、题目难度校正（0.15）、复核稳定度（连续正确，0.10）、对话隐式信号（0.10，平滑降权）、费曼批改（0.05）。映射五级阈值：<0.2 未接触、0.2–0.45 初学、0.45–0.7 熟悉、0.7–0.85 精通、>0.85 贯通（贯通需连续 3 次不同角度正确 + 费曼通过）。
- **Rationale**: 规则加权可解释、可审计、无需大量标注即可上线；符合 spec FR-012「正确率+难度+复核综合判定」。后期若数据充足可切换贝叶斯知识追踪（BKT/IRT）。
- **Alternatives**: ①纯 BKT/IRT——需大量作答数据冷启动难，P0 不适用；②单一正确率——无法体现对话与难度，放弃。

## D2 题目来源与正统性门禁

- **Decision**: 专家题库为主，AI 辅助出题为辅；**任何题目入题库前**须：溯源锚定 TextChunk（chunk_id）+ 过 TripleCheck（事实/术语/立场）+ 标注权威性状态（待审/已审）。AI 生成的候选题默认「待审」，未审题可用于"练习"但不得计入正式掌握度。错误诊断题的"故意错误项"打豁免标记，避免防偏离误拦。
- **Rationale**: 直接满足 spec FR-022/FR-023、SC-007；这是产品命门（正统性）。复用既有 TripleCheck 与溯源能力。
- **Alternatives**: ①纯 AI 出题——无法保证正统性且无溯源，违背项目红线，否决；②纯人工出题——内容生产慢，用 AI 辅助+人工审折中。

## D3 知识点依赖图存储

- **Decision**: 生产用 Neo4j（KnowledgeNode 节点 + PREREQUISITE_OF 边），开发/P0 用 in-memory 邻接表（复用 `HybridRetriever` 已有 in-memory 图模式），接口统一为 `KnowledgeGraphService`，环境驱动切换。
- **Rationale**: 与 001 的 retriever 降级策略一致，不阻塞 P0；图查询（前置闭包、阻塞章节数）在 Neo4j 更自然。
- **Alternatives**: 纯关系表递归查询——深层依赖查询繁琐，作为 in-memory 实现的兜底。

## D4 推荐算法

- **Decision**: 规则优先（可解释）：①门控——本章掌握分 ≥0.8 解锁下一章；②起点推荐——摸底测后按"已掌握可跳过/薄弱需先补"排序输出；③薄弱点排序 key = `(1-掌握分) × 依赖出度 × 考频权重`；④回补推荐——被后续 N 章依赖的薄弱点优先。所有推荐附一句话理由（模板 + 数值填充）。
- **Rationale**: spec FR-016/FR-019/FR-020 要求"理由可解释"，规则法直接产出理由；无需 ML 冷启动。后续可叠加排序学习。
- **Alternatives**: 强化学习/协同过滤——冷启动与可解释性差，P0 不做。

## D5 P0 内容规模与路线映射

- **Decision**: P0 只做「提纲」单章完整闭环（知识点树、题库 8–12 题/四类题型）。三路线定义为元数据（复用 路径.txt 书单映射章节），公共地基=学习顺序2.md 阶段 0–2 核心；A/B/C 支线章节先占位，题库分批扩展。路线/章节/门槛/题量均为可配置参数。
- **Rationale**: 控制内容生产成本，先把机制跑通（spec Assumptions 交付范围）。
- **Alternatives**: 一次性铺满 25 本书——内容与专家审核成本过高，周期长，否决。

## D6 隐式学情信号采集

- **Decision**: 在 `DialogueService` 内埋点上报 `StruggleSignal`：反复追问同概念（N 次）、追问后卡顿/短回复、被驳回、关联模式失败；权重低（0.10）并做时间衰减平滑，避免噪声主导。协议层落地既有已定义的 `STRUGGLE_DETECTED` / `PROGRESSION` 消息。
- **Rationale**: spec FR-009 要求对话驱动学情；既有协议已预留消息类型，落地成本低。
- **Alternatives**: 仅靠测试——丢失对话信息，体验割裂，否决。

## D7 跨设备同步与冲突

- **Decision**: 学情/进度以服务端为准，客户端本地缓存 + 断点续学；冲突以"最近一次有效学习"合并，历史作答全量留存不覆盖。作答离线本地暂存，恢复网络批量同步。
- **Rationale**: 满足 NFR-004；Flutter 端已有 WebSocket/HTTP，增量同步即可。
- **Alternatives**: 纯本地存储——跨设备丢失，否决。
