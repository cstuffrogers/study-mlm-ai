# 功能规格：学习勋章系统（achievement-badge-system）

## Overview

为提升学习积极性，本项目新增一套**学习勋章系统**。系统围绕学习者已有的学习行为指标（掌握知识点数、贯通知识点数、达成里程碑数、答对题数、完成路线、连续学习天数、对话学习次数）设计一整套勋章，当学习者达成某个勋章的获取条件时，触发一次「像抽中礼物一样」的获得动画；同时在**功能中心**新增「我的勋章」入口，集中展示已获得与未获得的勋章、每个勋章的获取条件及当前进度。

勋章系统完全由数据驱动：勋章目录与获取条件以配置形式维护，新增勋章不需要改动学习事件处理逻辑。学习者还可将「我的勋章」页面一键生成勋章收藏卡，分享到微信、朋友圈、QQ 等外部渠道，展示学习成果。

## Goals / Non-Goals

**Goals（目标）**

- 提供覆盖主要学习行为的勋章体系，让学习成果可视化、可收集，提升学习积极性。
- 勋章达成被系统自动检测并记录，首次达成时通过礼物开箱式动画给予即时正反馈。
- 提供「我的勋章」页面：已获得勋章（含获得时间）与未获得勋章（含获取条件与当前进度）一目了然。
- 提供勋章分享：将勋章收藏卡以图片形式一键分享到微信、朋友圈、QQ 等外部渠道，展示学习成果。
- 勋章目录可配置、可扩展，条件判定与学习事件解耦。

**Non-Goals（非目标）**

- 不做勋章交易、转让、排行榜、勋章商城或实体兑换。
- 不做多级晋升体系（同一勋章的青铜/白银/黄金分级）；每个勋章为单一达成条件。
- 不做学习行为本身的改变（勋章只做激励反馈，不改变答题、路线、对话的既有规则）。
- 不做站内社交体系（好友、关注、动态流）；分享仅指将勋章收藏卡图片分享到系统级分享渠道（微信、朋友圈、QQ 等），不自建分享平台。

## User Scenarios

### US1（P1）：学习事件触发勋章达成检测

学习者在完成答题、掌握知识点、完成路线、完成对话学习等学习行为后，系统在事件处理流程中自动评估其各项学习指标，对照勋章目录判定是否有新勋章达成，并记录授予记录（含达成时间与来源事件）。每个勋章对每个学习者只授予一次，重复事件不产生重复授予、不重复触发动画。

**验收**：当学习者的掌握知识点数从 9 提升到 10 时，若存在「掌握 10 个知识点」勋章，则该勋章被自动授予并记录；再次答题不会重复授予。

### US2（P1）：新勋章获得动画

学习者首次达成某勋章时，客户端播放「礼物开箱」风格的获得动画（礼盒开启、光效与粒子效果、勋章展示），动画结束后展示勋章名称、描述与获取条件。用户在动画播放中途退出时，不产生任何异常状态，之后可从首页提醒或「我的勋章」重新触发查看。

**验收**：首次达成勋章时必播放动画；同一勋章第二次达成条件变化（如指标继续增长）不再播放该勋章的获得动画。

### US3（P1）：功能中心「我的勋章」页面

学习者在功能中心点击「我的勋章」进入勋章页面，页面按分类展示：

- **已获得勋章**：勋章图标、名称、描述、获取条件、获得时间。
- **未获得勋章**：勋章图标置灰/占位展示、名称、描述、获取条件，以及当前进度（如「3/10」）。

支持按分类筛选；点击单个勋章可查看详情。页面加载时能一次性获得全部勋章的授予状态与进度。

**验收**：新用户进入页面时，全部勋章以未获得状态展示并带获取条件；达成某勋章后再进入，该勋章出现在已获得分组且显示获得时间。

### US4（P2）：首页新勋章提醒

当学习者存在尚未查看的新勋章（未播放动画、未标记已读）时，首页展示新勋章提醒入口；点击提醒可触发获得动画，或直接进入「我的勋章」页面。提醒在用户查看后消失。

**验收**：获得新勋章后回到首页可见提醒入口；查看（播放动画或标记已读）后提醒消失；无新勋章时不显示该入口。

### US5（P2）：分享勋章收藏卡

学习者在「我的勋章」页面点击「分享」入口，系统将当前已获得勋章渲染为一张勋章收藏卡图片（含学习者称号、已获得勋章数量与勋章墙），并调起系统分享面板，可将图片分享到微信、朋友圈、QQ 等任意支持图片分享的渠道。分享内容在客户端本地生成，不上传服务端。

**验收**：点击分享后，本地即时生成收藏卡图片并打开系统分享面板（原生客户端）；Web 端在支持 Web Share API 时调起系统分享，不支持时回退为复制分享文案到剪贴板并提示手动粘贴。

### 备选场景

- **离线学习**：学习者在无网络状态下完成的学习行为，勋章达成检测与「我的勋章」进度展示在客户端本地完成，联网后授予记录同步至服务端，服务端为最终权威（方案 A，已确认，见 Clarifications）。
- **指标波动**：学习者连续学习天数中断后重新计算，或答题记录被清理：已获得的勋章不被回收，仅影响未获得勋章的进度展示。

## Functional Requirements

### FR-01 勋章目录定义

系统维护一份勋章目录，每枚勋章包含：唯一标识、名称、描述、分类、获取条件（阈值型或完成型）、用于进度展示的指标、展示图标标识、展示排序、启用状态。初始勋章目录按下方「勋章目录（初始设计）」执行，后续可通过配置增删改。

### FR-02 学习指标采集

系统持续采集以下学习指标（口径与现有系统一致）：

1. **掌握知识点数**：掌握度达到「已掌握」级别的知识点数量（含费曼通过要求）。
2. **贯通知识点数**：累计进入过深入学习的去重知识点数量（对应指标键 `journey_count`）。
3. **达成里程碑数**：动机系统中生成且已达成的里程碑数量。
4. **累计答对题数**：测验与复习中判定为正确的作答累计数。
5. **完成路线数**：完成整条路线学习（路线内全部节点达到掌握或测验通过）的路线数量。
6. **连续学习天数**：动机系统计算的连续学习天数。
7. **完成对话数**：完成的对话学习场次数。

> 注：「累计作答题数」作为**辅助指标**与「累计答对题数」配套采集，用于正确率类勋章（如「精准之声」）的条件判定与进度展示。

### FR-03 达成检测与授予

- 学习行为事件（答题、掌握度更新、路线完成、对话完成、每日学习结算）发生后，系统立即对照勋章目录进行一次达成检测。
- 检测命中且该用户尚未持有该勋章时，生成授予记录，记录达成时间与来源事件，并标记为「未查看」。
- 检测具有幂等性：同一事件重复处理、或指标在多次事件间持续达标，均不产生重复授予记录。
- 已获得的勋章永不回收，指标后续波动不影响已授予记录。

### FR-04 获得动画

- 首次获得勋章时，客户端展示礼物开箱式获得动画，动画包含礼盒开启过程与勋章揭晓，总时长不超过 5 秒（建议 2–4 秒，保证「一次抽奖/开礼物」的完整仪式感且不拖沓）。
- 动画展示勋章名称、描述与获取条件，可标记为已查看。
- 动画中途退出不产生错误状态，允许之后重新触发（从首页提醒或勋章详情）。
- 同一勋章仅首次达成时播放该动画。

### FR-05「我的勋章」页面

- 功能中心新增「我的勋章」入口，点击进入勋章页面。
- 页面展示全部勋章，分为「已获得」与「未获得」两组（或按分类 + 状态标记展示，交互细节在设计阶段定稿）。
- 已获得勋章展示：勋章图标、名称、描述、获取条件、获得时间。
- 未获得勋章展示：勋章图标（置灰/占位）、名称、描述、获取条件、**当前进度**（按该勋章对应的指标展示，如「3/10」或「已连续学习 5/7 天」）。复合条件勋章（如「精准之声：累计作答 ≥50 题且正确率 ≥90%」）按主指标展示进度并附正确率，如「作答 30/50，正确率 80%」。
- 支持按勋章分类筛选；点击勋章展示详情（含获取条件与进度）。
- 页面数据一次性加载，包含全部勋章的授予状态与当前进度。

### FR-06 首页新勋章提醒

- 存在未查看的新勋章时，首页展示提醒入口。
- 点击提醒：优先触发获得动画，动画结束后可进入「我的勋章」；或直接进入「我的勋章」页面。
- 用户查看后（动画完成或显式标记已读），提醒消失。

### FR-07 勋章目录可配置

- 新增、修改、停用勋章仅需修改勋章目录配置，不要求改动任何学习事件处理代码。
- 停用的勋章不再参与检测，但已授予记录保留展示，并在页面中标记为「已停用」。

### FR-08 勋章分享（收藏卡）

- 「我的勋章」页面提供「分享」入口，将当前用户的已获得勋章渲染为**勋章收藏卡**图片：包含收藏卡标题（应用名）、学习者已获得勋章总数、勋章墙（已获得勋章的图标与名称，按分类排列）、分享文案。
- **原生客户端（Android/iOS）**：将收藏卡图片写入本地临时文件，调起系统分享面板（share_plus），用户可选择微信、朋友圈、QQ 等任意支持图片分享的渠道完成分享。
- **Web 端**：优先使用 Web Share API（`navigator.share`，携带图片文件）调起系统分享；浏览器不支持时，回退为将分享文案复制到剪贴板，并提示用户到微信/QQ 手动粘贴。
- 收藏卡图片由客户端实时渲染生成，不落服务端、不上传服务器；未获得勋章不参与收藏卡渲染。
- 分享入口位于「我的勋章」页面标题栏；分享不改变任何授予/查看状态。

## Data Model（关键实体）

- **勋章定义（BadgeDefinition）**：badge_id（唯一）、名称、描述、分类、条件类型（阈值型/完成型）、阈值、进度指标、图标标识、排序、启用状态。目录以配置形式维护（见 FR-07）。
- **勋章授予记录（BadgeAward）**：用户、勋章标识、授予时间、来源事件、查看状态（未查看/已查看）。约束：同一用户同一勋章至多一条授予记录。
- **学习指标快照（LearningMetrics，派生）**：FR-02 中 7 项指标的当前值，用于条件判定与进度展示，不单独持久化，由现有学习数据实时汇总。
- **勋章收藏卡（ShareCard，客户端派生）**：分享功能不产生任何后端数据。收藏卡图片由客户端根据 `GET /api/badges/mine` 返回的已获得勋章实时渲染生成，即时分享、即用即弃，不上传、不存储。

## Success Criteria

- **SC-01**：学习事件（答题、掌握更新、路线完成、对话完成、每日结算）处理完成后，新勋章的达成检测随之完成，用户无需额外操作、无可见延迟。
- **SC-02**：每枚勋章对每个用户恰好授予一次；重复事件与指标持续达标均不产生重复授予记录，不重复播放获得动画。
- **SC-03**：「我的勋章」页面完整展示勋章目录中全部勋章；已获得勋章显示获得时间，未获得勋章显示获取条件与当前进度。
- **SC-04**：未获得勋章的进度与该用户真实学习指标一致（如掌握 3 个知识点时，「知识学人」显示 3/10）。
- **SC-05**：首次达成勋章时客户端播放礼物开箱式动画（总时长不超过 5 秒）；中途退出后可从首页提醒或勋章详情重新触发，且不产生重复授予记录。
- **SC-06**：无新勋章时首页不显示提醒入口；存在未查看新勋章时首页显示提醒，查看后消失。
- **SC-07**：新增一枚勋章仅需修改目录配置即可生效（自动参与检测、展示与进度计算），无需改动学习事件处理代码。
- **SC-08**：指标波动（连续天数中断、记录清理等）不回收已获得勋章，「我的勋章」页面数据保持一致。
- **SC-09**：在「我的勋章」页面点击分享，原生客户端 2 秒内生成收藏卡图片并调起系统分享面板（可分享至微信、朋友圈、QQ 等）；Web 端支持 Web Share API 时调起系统分享，不支持时成功复制分享文案并给出提示。
- **SC-10**：分享收藏卡内容与「我的勋章」页面已获得勋章一致（数量、名称、分类），且分享操作不改变任何授予记录与查看状态。

## Assumptions

- 功能中心已存在于首页（home_screen 的头部入口区），「我的勋章」以新入口形式加入，不改变现有入口结构。
- 获得动画为首次达成专属，不做回放入口（可在后续版本按需增加）。
- 指标口径与现有系统一致：掌握 = 掌握度达「已掌握」（含费曼通过）；贯通 = 累计进入深入学习的去重知识点数；里程碑 = 动机系统已达成的里程碑；答对 = 测验/复习判定正确；路线完成 = 路线内全部节点掌握或测验通过；连续学习 = 动机系统计算的连续天数；对话完成 = 完成一次对话学习。
- 勋章目录阈值（初始设计表中的数量）为建议值，实施阶段可依据系统实际体量微调，但分类与判定结构不变。
- 离线模式采用方案 A：在线与离线均支持，客户端本地评估与展示，联网后同步授予记录，服务端为最终权威（已确认，见 Clarifications）。
